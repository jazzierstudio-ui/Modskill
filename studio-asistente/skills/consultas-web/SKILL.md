# Consultas y peticiones de la web

## 1. Recoger
- **Gmail** (si está conectado): busca hilos recientes sin responder con términos como `formulario`, `contacto`, `presupuesto`, `sesión`, `reserva`, `información`, `precio`, y los remitentes del formulario de la web (WordPress/Wix/Squarespace/Webflow…) desde la última revisión anotada en `~/.studio-asistente/consultas.md` (si no hay, últimos 7 días).
- Si no hay conector, pide al usuario que pegue los mensajes o capturas.
- Lee `consultas.md` para detectar seguimientos pendientes (presupuestos enviados sin respuesta hace más de 3 días).

## 2. Priorizar
Clasifica cada consulta: 🔴 urgente (fecha próxima, cliente listo para reservar), 🟡 normal, ⚪ baja (spam, colaboraciones dudosas, sin datos). Extrae: nombre, servicio, fecha deseada, presupuesto, canal, dudas concretas.

## 3. Responder
Para cada consulta relevante redacta un borrador corto en el tono del perfil: saludo personal, respuesta a lo que pregunta, propuesta (paquete o precio si está en el perfil; si no, pregunta al usuario los precios y guárdalos), 2-3 huecos reales del calendario si hay conector, y un siguiente paso claro. Crea los borradores en Gmail solo tras confirmar; **nunca envíes**.

Si piden presupuesto, prepara una tabla clara (servicio, incluye, entrega, precio, condiciones/señal) y ofrece exportarlo (docx/pdf) o usar la plantilla de Drive.

## 4. Registrar
Actualiza `consultas.md` (fecha, cliente, servicio, estado, próxima acción, fecha de seguimiento). Termina con un resumen: X nuevas, Y urgentes, Z borradores listos, seguimientos para hoy. Si se repiten las mismas preguntas, propón añadir una FAQ a la web (y pásalo a metricas-seo).
